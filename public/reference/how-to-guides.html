🔧 How-to Guides

Step-by-step troubleshooting and configuration guides for real-world IT scenarios

Troubleshooting PC Won't Boot — Systematic Diagnosis

▼
1
Check power supply

Verify the power cable is connected, PSU switch is ON, and the outlet works. Listen for fan spin. No lights at all = PSU or motherboard failure.

2
Listen for POST beep codes

One short beep = successful POST. Repeated beeps or patterns indicate specific failures (RAM, GPU, CPU). Consult your motherboard manual for codes.

3
Check display connection

Ensure monitor cable is firmly connected. Try a different port (HDMI vs DisplayPort). If using discrete GPU, connect to GPU not motherboard.

4
Reseat RAM and GPU

Power off, unplug, ground yourself. Remove and firmly reseat RAM sticks and GPU. Try one RAM stick at a time to isolate faulty module.

5
Check BIOS/boot order

If POST succeeds but OS won't load: enter BIOS, verify boot drive is listed and set as first priority. Check for No boot device found errors.

6
Use WinRE if needed

Boot from Windows install media → Repair your computer → Startup Repair. If that fails: bootrec /rebuildbcd from Command Prompt.

Always work through the CompTIA 6-step troubleshooting methodology: Identify → Theory → Test → Plan → Verify → Document.

Troubleshooting No Internet — Network Connectivity Diagnosis

▼
1
Check physical connection

Ethernet: verify cable is plugged in, check link lights. Wi-Fi: confirm connected to correct SSID, check airplane mode is off.

2
Check IP configuration

Run ipconfig (Windows) or ip addr (Linux). If you see 169.254.x.x (APIPA), DHCP failed. Try ipconfig /release then ipconfig /renew.

3
Ping loopback

ping 127.0.0.1 — if this fails, TCP/IP stack is broken. Reinstall network adapter or run netsh winsock reset.

4
Ping default gateway

ping [gateway IP] — if fails, local network issue (cable, switch, router). Check other devices on same network.

5
Ping external IP

ping 8.8.8.8 — if fails but gateway works, router can't reach internet. Check ISP connection, reboot modem/router.

6
Test DNS

nslookup google.com — if IP ping works but names don't resolve, DNS is the issue. Try ipconfig /flushdns or change DNS to 8.8.8.8.

This flow isolates the problem layer by layer: Physical → IP → Local → WAN → DNS. Master this for the exam.

Security Malware Removal — 7-Step Process

▼
1
Investigate and verify symptoms

Slow performance, pop-ups, unexpected processes, browser redirects, disabled antivirus. Confirm infection before acting.

2
Quarantine the system

Disconnect from network immediately to prevent spread. Disable Wi-Fi and unplug Ethernet. Do NOT power off (preserves evidence in RAM).

3
Disable System Restore

Prevents malware from hiding in restore points. Delete existing restore points that may be infected.

4
Remediate — scan and remove

Boot to Safe Mode (F8 or msconfig). Run full scan with updated antimalware. Use multiple tools: Windows Defender + Malwarebytes. Remove all detected threats.

5
Schedule follow-up scans

Set antimalware to run automatic daily/weekly scans. Update all definitions. Check that real-time protection is re-enabled.

6
Re-enable System Restore

Create a new clean restore point. Delete old (potentially infected) restore points.

7
Educate the user

Explain how infection occurred. Train on safe browsing, email link awareness, download sources. This is the FINAL step — always.

CompTIA's exact order: Investigate → Quarantine → Disable Restore → Remediate → Schedule scans → Enable Restore → Educate. Memorize this.

Configuration Secure a SOHO Wireless Router

▼
1
Change default credentials

Default admin/admin is the #1 SOHO vulnerability. Set a strong unique password for the admin panel immediately.

2
Update firmware

Check manufacturer site for latest firmware. Updates patch known vulnerabilities. Enable auto-update if available.

3
Set WPA3 (or WPA2-AES minimum)

Never use WEP or WPA-TKIP. Set a strong passphrase (12+ characters). If WPA3 isn't supported by all devices, use WPA2-AES.

4
Disable WPS

Wi-Fi Protected Setup has a known PIN vulnerability (brute-forceable). Always disable it in router settings.

5
Disable remote management

WAN-side admin access lets attackers configure your router from the internet. Disable unless specifically needed.

6
Set up guest network

Isolate IoT devices and visitors on a separate SSID. Prevents guests from accessing your main network resources.

7
Disable UPnP

Universal Plug and Play auto-opens ports — exploitable by malware. Disable and manually forward only needed ports.

Exam loves this topic. Remember: change defaults, update firmware, WPA3, disable WPS, disable remote mgmt, guest network, disable UPnP.

Troubleshooting Windows System File Repair

▼
1
Run SFC first

Open elevated Command Prompt. Run sfc /scannow. Wait for completion. If it reports "found corrupt files and repaired" — done.

2
If SFC fails → run DISM

If SFC says "could not fix some files," the component store is corrupted. Run: DISM /Online /Cleanup-Image /RestoreHealth

3
Retry SFC after DISM

DISM repairs the source that SFC uses. After DISM completes, run sfc /scannow again. It should now succeed.

4
Check Event Viewer

Look in Windows Logs → System for related errors. CBS.log at C:\Windows\Logs\CBS\CBS.log has detailed SFC results.

The order matters: SFC first → DISM if SFC fails → SFC again. Never skip straight to DISM.
